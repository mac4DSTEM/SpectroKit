# tools/edx-stages: generators and pins for the EDX stage gates

Contract: `docs/edx-stage-gates-registration.md` (23fa2af). Reference venv `References/exspy-venv` (HyperSpy 2.4.0, NumPy 2.5.4,
SciPy 1.18.1, h5py 3.16.0), run `-I -B`. Fixtures: `Tests/SpectroEDXTests/Fixtures/` (15 MB).

## Run order (all deterministic; two full runs wrote identical bytes, sha256 compared)
1. `References/exspy-venv/bin/python -I -B tools/edx-stages/make_planted.py` (NumPy only; 0.4 s) -> `edx-planted*.{json,f64,i16}`, `edx-calibration*`.
2. `References/python-venv/bin/python -I -B tools/edx-stages/make_velox_streams.py` (h5py) -> `velox-stream-*.emd`, `velox-streams-truth.json`.
3. `References/exspy-venv/bin/python -I -B tools/edx-stages/pins.py` (about 110 s) -> `pins.json`, `edx-axis-e2.f64`, `edx-pins-intensity.f64`.
4. `... tools/edx-stages/findings.py` prints the numbers below (not a fixture writer).
Docstrings of each script define every parameter; this file lists readings made and findings.

## Formats the Swift tests read
- `edx-planted.json`: `k0` 96, `nwin` 1056 (channels 96..1151 of 4096 stored; E_k = -1.93221348 + 0.02 k), `cells[]` {id, set, family s|L, N_Al, rho_Mg (Python reprs as strings), mean_row, resid_row0, n_real, seed, real_total_full/window}. Counts of realisation j (0-based) = `rint(means[mean_row]) + resid[resid_row0 + j]` (round half to even). `edx-planted-means.f64` float64 LE (ncell, 1056); `edx-planted-resid.i16` int16 LE (nreal, 1056). Channels outside the window are not stored (the proposer range 0.2-20 keV is inside). 430 cells, 3950 realisations. `edx-planted-truth.json`: per cell id, areas {Mg, Al, Si, O, Ar, sum_AlAl} (counts, repr strings) and generator parameters. Sets: M, S+-{1,2,3,5,10}, HALF, T{1,2,5}, U{125,130,140,150}, C1, C2, B, W{1,2,4,6}, X (definitions in make_planted.py).
- `edx-calibration.json` + `edx-calibration-counts.u32` (uint32 LE, rows of 192 channels from channel 96): 192 cells x (3 or 1) rows; `true_axis` offset/scale per cell.
- `velox-stream-*.emd` (6 files, 50-206 KB) + `velox-streams-truth.json`: the draw (events per stream/frame/pixel, channel sums, pixel totals, expected axis in eV, expected `energyCalibrationAgrees`).
- `pins.json` (2 MB, structure in the pins.py docstring), `edx-axis-e2.f64` (float64 query values; indices in pins.json axis.e2.index, null where HyperSpy raises), `edx-pins-intensity.f64` (float64, 2190 x 6; row map in pins.json lines.intensity.cells).
- Public Velox files are NOT copied: pins.json holds their decode (per-stream sparse channel sums, pixel totals, `dense_sha256` of the summed uint32 (y,x,channel) cube). The Swift test must unzip them from `References/rosettasciio` itself.

## Readings made (registration silent or ambiguous)
- Matched set M uses exSpy's table energies/weights (asserted equal to exSpy in pins.py), not the booklet ones (5.2 says booklet; criterion 3 needs table). Booklet lines are in U, B and the calibration set.
- Fano constant 8 ln2 (registration: 2.3548^2). Reproduces 79.0 / 82.3 / 85.8 eV and FN 72.7 / 76.6 / 80.6 eV at R 130.
- "In-family" continuum = the realistic (roll-off A) shape projected by NNLS onto the Kramers x Bernstein (9,5) cone (own Lawson-Hanson; equals SciPy's to 2e-16). Measured rho_c: family s 0.00083, L 0.0082.
- C2 absorption step applied to the shape before normalising; HALF evaluated at E_k + 0.01 (identical to S-10 for the lines).
- Realisation budget (15 MB): M/s 100 at all 28 cells; M/L 20 at N 1e6, 1e7 x rho {0,.002,.01,.05}; U130 20 (s and L) over N {1e5,1e6,1e7} x rho {0,.002,.01,.05}; U125/140/150 20 at N 1e7 x rho>0; all other sets 5 at N 1e7 x rho {.002,.01,.05}; every set also has noise-free means (N 1e5..1e7 x rho {0,.002,.01,.05}). Not full-pool-5 on a "reduced grid" of the registration's own choosing; the lead may widen it (cost 2 KB per spectrum).
- Extra sets W1..W6 (7.3's width rows) and B were added; calibration set uses 3 realisations at N 1e6 and 1 at N 1e7.
- Pile-up truth: Ar = 0, `sum_AlAl` = 1e-3 N_Al.
- Grid of the public files = ScanSize x ScanArea (as VeloxEMDReader), rsciio's last-image grid recorded beside it.
- `sparse` is not installed: no rsciio loader; the oracle for counts is the NumPy decoder (equals the published constants and the planted draws).
- DTSA-II (P4) and real data: not touched.

## Findings
**C (counts).** NumPy decode of `fei_SI_EDS-HAADF-4detectors_2frames.emd`: 916174 / 867647 / 913682 / 865236 events per stream in name order, 3562739 total, 512 markers per stream: equals the published constants (asserted, the script stops otherwise). Streams decoded for 8 public files (4detectors, three SuperX 10x50, fei_emd_si, EELS_EDS, SI_empty selection, Test SI 16x16; the ReducedData file has an empty stream group: skipped). `fei_emd_spectrum.emd` has a stream group whose grid is unresolved (skipped, reported). `example_velox_EELS_EDS.emd`: ScanSize x ScanArea 16 x 20 vs rsciio's last-image 128 x 128 (known deviation). Planted files: decode equals the draw for every frame range (self-check, passed). exSpy `sum()` of a uint16 image: dtype uint64, equals NumPy uint64 (max 131077 from two 65535), `live_time` 2.0 -> 40.0 over 20 pixels. Predicted outcome met.
**E (axis).** rsciio's `_get_dispersion_offset` (ast-cut, sha256 asserted) agrees with the hand-written expectations on all six planted files: 4 streams offsets -1.0/-1.0/-0.996/-1.0 keV (calibration must disagree), decoy picks (0.01, -0.5), axis-order picks Detector-10 (0.02, -1.9) by FILE order. Possible Swift deviation (read, not run): `VeloxEMDReader` sorts `detectors` by index before the "first whose name contains" rule, which would pick Detector-2 (10, -0.5) on `axis-order`. E3, exSpy `calibrate_energy_axis("offset")` (offset change vs -delta, eV): N 1e6 (288 fits) mean +0.03, max |err| 0.71; N 1e7 (96) mean +0.02, max 0.62. By gain: -3e-4 mean +0.46, 0 mean +0.03 (max 0.29 at 1e6, 0.15 at 1e7), +3e-4 mean -0.41. **Registered prediction "within +-0.2 eV at N_Al >= 1e6" is FALSE when the gain is off (max 0.71 eV) and marginally false at gain 0, N 1e6 (0.29 eV; measured 0.1 in the probe at one cell).** `"scale"` mode returns scale 0.0199577 for every planted gain (true 0.0200060 / 0.0200000 / 0.0199940): it does not recover gain here (and alters the cropped offset). `"resolution"` raised "FWHM_MnKa ... smaller than physically possible" in 2 of 384 fits. The Swift refinement bound (1 eV, 1e-4) is untested yet.
**P (peaks).** P1: **exSpy's `get_xray_lines_near_energy` order for exactly tied |dE| lines is not reproducible** (it iterates a hash-ordered element dict; the pins list differed between two processes). The registered "same order including ties" cannot be a contract; pins store canonical (|dE|, name) order (45 tied adjacent pairs in 360 cases). Window-method bias (exSpy windows, Mg net at rho_Mg = 0, noise-free mean of the generator): U130 family s -134 / -1335 / -13353 at N 1e5 / 1e6 / 1e7; family L -129 / -1292 / -12922; M/s -117 / -1174 / -11744.
